## 二、通用

### 2.1 操作状态轮询

前端发起任何耗时操作后，会轮询一个统一的状态端点来驱动进度条。

```
GET /api/v1/operations/{operation_id}/status

Response 200:
{
  "operation_id": "op_abc123",
  "type": "fetcher_rerun | simulation_trigger | verification_run | approval",
  "status": "accepted | running | completed | failed",
  "progress": 0-100,
  "progress_message": "正在加载 GDELT 数据...",
  "result": { ... } | null,
  "error": { "code": "...", "message": "..." } | null,
  "created_at": "ISO8601",
  "completed_at": "ISO8601" | null
}
```

| ❓ | 请回复 |
|---|---|
| 2.1.1 | 这个统一状态端点**现在有吗**？如果没有，各模块是否有各自的 status 端点可适配？ |

## 三、天枢（macro-scan · 观测层运维）

### 3.1 获取采集器（fetcher）列表

```
GET /api/v1/tianshu/fetchers

Response 200:
{
  "fetchers": [
    {
      "id": "gdelt_v1",
      "name": "GDELT 采集器",
      "status": "running | paused | error",
      "interval_seconds": 3600,
      "last_run_at": "ISO8601" | null,
      "last_status": "success | failed | null"
    }
  ]
}
```

| ❓ | 请回复 |
|---|---|
| 3.1.1 | fetcher 列表有现成接口吗？若有，端点是什么？ |
| 3.1.2 | 如果没有——有地方能看到所有 fetcher 的状态吗（scheduler 内部状态 / 配置文件 / observability？） |

### 3.2 重跑 fetcher

```
POST /api/v1/tianshu/fetchers/rerun
Body:
{
  "fetcher_ids": ["gdelt_v1", "fred_v1"],
  "idempotency_key": "uuid-v4"
}

Response 202:
{
  "operation_id": "op_abc123",
  "status": "accepted",
  "affected_fetchers": ["gdelt_v1", "fred_v1"]
}
```

| ❓ | 请回复 |
|---|---|
| 3.2.1 | 有没有 API 可以手动触发单个/批量 fetcher 重跑？ |
| 3.2.2 | 如果没有——scheduler 有没有信号机制（如写文件、发信号）可被包装成 API？ |

### 3.3 暂停 / 恢复 fetcher

```
POST /api/v1/tianshu/fetchers/{fetcher_id}/pause
POST /api/v1/tianshu/fetchers/{fetcher_id}/resume
```

| ❓ | 请回复 |
|---|---|
| 3.3.1 | 有没有暂停/恢复采集源的接口？ |

### 3.4 调整采集频率

```
PUT /api/v1/tianshu/fetchers/{fetcher_id}/config
Body: { "interval_seconds": 7200 }
```

| ❓ | 请回复 |
|---|---|
| 3.4.1 | 频率可在线调整吗？还是必须改配置重启？ |
