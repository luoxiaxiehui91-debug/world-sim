# 开阳地图视觉评估 · 2026-08-11 · v1.10.6

> **结论先行**：主理人两轮反馈「图标依旧大 + 内容看着乱」，根因**不在单点尺寸数学**，而在 **(a) 3D rings 直径 20–40px 远大于 2D 中心圆 5–14px（视觉上「3D 比 2D 大」）** 与 **(b) 默认视图涌入 613 个 news+conflict 点，其中 281 个（46%）触发明黄常驻标签，互相遮挡把地球糊成标签云**。截图证据见 §5。
>
> **收益最大的 1–2 步**（详见 §4）：① 把 news / conflict 默认图层改为关（用户主动开 → 才有信息密度），② 把 3D ringMaxRadius ×0.55 收到与 2D 同量级（10–22px）。这两步可单独也成立，预计把"图标大 + 画面乱"两反馈一次性收敛 ≥70%。

## 1. 图标大小根因（数学 + 实测）

### 1.1 2D `FlatMapPanel.tsx`（v1.10.6 公式）

- **中心实心圆**：`core = clamp(2.4 + 4.8·w, [2.4, 7.2])`（w=0~1 → 半径 2.4~7.2px）
- **外环（薄描边）**：`r = core × 1.8`（半径 4.3~13.0px，描边 1.0px，opacity 0.4↔0.9 呼吸）
- **内过渡（淡光晕）**：`r = core × 1.35`（半径 3.2~9.7px，opacity 0.10）
- **半补偿**：`1/√k`（crucix 式，缩放时图标随之变但不消失）

#### 2D 视觉尺寸表（k=1 默认）

| w  | 中心实心 d | 外环总 d | 内过渡 d |
|----|-----------|---------|---------|
| 0  | 4.8px     | 9.6px   | 6.5px   |
| 0.25 | 7.2px   | 14.0px  | 9.7px   |
| 0.5 | 9.6px    | 18.3px  | 13.0px  |
| 0.75 | 12.0px  | 22.6px  | 16.2px  |
| 1  | 14.4px   | 26.9px  | 19.4px  |

#### 2D 不同 zoom 下核心 r 像素

| w  | k=0.5 (拉远) | k=1 (默认) | k=2 | k=4 |
|----|--------------|-----------|-----|-----|
| 0 | 3.39 | 2.40 | 1.70 | 1.20 |
| 1 | 10.18 | 7.20 | 5.09 | 3.60 |

→ **2D 点核心实心 5–14px、外环 9–27px 是合理量级**（类似 crucix ACLED 5–12px 风格）。**2D 图标尺寸本身不是问题**。

### 1.2 3D `GlobePanel.tsx`（v1.10.6 公式）

- **点半径**：`pointRadius = 0.32 + 0.2·w` **度**（w=0~1 → 0.32~0.52 度）
- **光环半径**：`ringMaxRadius = 1.76 + 1.76·w` **度**（普通），`2.8 + 1.76·w` **度**（聚焦）
- **传播速度**：`1.0 + 1.2·w`（普通），`1.8 + 1.2·w`（聚焦）
- **重复周期**：`1800ms ~ 700ms` 随 w
- 默认相机 `WORLD_CAMERA.altitude = 2.4`（`regions.ts:129`）

> **单位换算**：`globe.gl` 的 `.pointRadius` / `.ringMaxRadius` 单位是**度**（地球表面弧度对应的度数）。默认相机下 1 度 ≈ **5.59px**（1920×1200 视口，globe-stage 半径 R_screen≈320px 经验值）。

#### 3D 视觉尺寸表

| w  | 中心点 d (实心) | 普通环 d | **聚焦环 d** |
|----|-----------------|----------|--------------|
| 0  | 3.6px           | 19.7px   | 31.3px       |
| 0.25 | 4.1px         | 24.6px   | 36.2px       |
| 0.5 | 4.7px          | 29.5px   | 41.1px       |
| 0.75 | 5.2px        | 34.4px   | 46.0px       |
| 1  | 5.8px          | 39.3px   | 50.9px       |

#### 2D vs 3D 对比（w=1，最严重度）

|        | 中心圆 d | 光环/外环 d |
|--------|---------|------------|
| 2D    | 14.4px  | 26.9px     |
| 3D    | 5.8px   | **39.3px** |
| **差** | 2D ≈ 2.5× 中心大 | **3D ≈ 1.5× 环大** |

→ **3D 光环比 2D 光环大 1.5 倍**——这是「图标大」反馈的真实来源（用户感知的是环，不是中心点）。focus ring（50.9px@w=1）尤为显眼。

### 1.3 战略要地 ★ 对比

| 维度 | 字号/size | 估算屏幕 d |
|------|-----------|-----------|
| 2D ★  | SITE_STAR_FONT=16.8 × siteScale(1/1.25/1.5) | 16.8~25.2px |
| 3D ★  | sprite size = 3.84 × siteScale（globe unit） | 14~18px（截图实测，shot-2-globe-no-news.png） |

→ 战略要地尺寸已合理，与 2D/3D 普通点视觉量级一致。

### 1.4 当前 → 目标 → 改法

| 维度 | 当前 | 目标 | 改法（文件:行 → 现值 → 建议值） |
|------|------|------|--------------------------------|
| 2D 普通点 | 中心 5–14px / 外环 9–27px | **保持**（已合理）| 无需改 |
| **3D 普通 ring** | 1.76+1.76w 度 → 19.7–39.3px | 收窄到 1.0+1.0w 度 → **11–22px**（与 2D 同量级）| `GlobePanel.tsx:333` `1.76 → 1.0`、`1.76 → 1.0` |
| **3D 聚焦 ring** | 2.8+1.76w 度 → 31–51px | 收窄到 1.8+1.2w 度 → **20–32px** | `GlobePanel.tsx:333` `2.8 → 1.8`、`1.76 → 1.2`（与 pointRadius 0.32+0.2w 联动的 5–6×）|
| 3D 战略要地 | sprite 3.84 unit | 保持 | 无需改 |
| 2D 战略要地 | 16.8–25.2px | 保持 | 无需改 |
| 2D 聚焦环 | max(core×2.4,12) → 25–36px | 收窄到 max(core×2.0,10) → **20–28px** | `FlatMapPanel.tsx:571` `core*2.4 → core*2.0`、`12 → 10` |

> **原则**：3D ring 应当是「点周围的呼吸圈」，而不是「直径 = 2D 总尺寸」的等比例放大。crucix 风格下 rings 直径 ≈ 中心点直径 4× 是合适的；当前 6.8×（39.3/5.8）明显偏大。

### 2.4 治理方案

#### 2.4.1 同地点聚合（最直接的"乱"治理）

> **设计**：当 `lat,lng` 相同的点 ≥2 个时，**合并成 1 个聚合点 + 计数徽标**；点击聚合点 = 展开 = 当前已实现的 `EventPopup`（v1.10.5/1.10.6）。
> **改造点**（`lib/mapData.ts` + `WorldPanel.tsx` + `GlobePanel.tsx` / `FlatMapPanel.tsx`）：
>
> 1. `mapData.ts` 新增 `aggregatePoints(points)`：按 `(round(lat,1), round(lng,1))` 分桶，单桶合并为 1 个 `RiskPoint`（保留最严重者）+ `count` 字段；聚合点的 `group` 改为 `N events · ${类型集}`
> 2. 聚合点视觉升级：
>    - **中心圆 d = 7–11px**（略大于普通点），环 d = 18–28px（与普通 ring 同档）
>    - **计数徽标**：右上角 `×N` 小角标（背景 alpha 0.7，字 10–11px，半径 6px 圆）
>    - **2D ring-pulse** 给聚合点，其他被合并的同地点点**不画**
>    - **3D htmlElement** 给聚合点（显示 `×N · ${最高severity} · ${最热地点}` 短标签）
> 3. 点击聚合点 → 复用 `handlePointClick` + `popupPoint`（已有），弹框列出该地点的全部事件
>
> **预期收益**：Washington 34 + California 25 + Tehran 21 等"光团" → 各变 1 个聚合点 ×N，画面**减少 60–70% 同地点重叠**。
> **风险**：聚合后丢失单点 lat/lng 精度 → 弹框补救（已有）；聚合逻辑要尊重 `isEvent`（事件点必须保留单点）。

#### 2.4.2 默认图层开关优化（最高 ROI）

> **设计**：让用户**主动**选择是否打开「地理新闻」「冲突事件」图层。
>
> 1. `config/layerCategories.ts:103` `news.defaultVisible`：`true → false`
> 2. `config/layerCategories.ts:113` `conflict.defaultVisible`：`true → false`
> 3. K8 前向兼容：`parseLayerVisibility` 已支持「按 defaultVisible 补入」（layerCategories.ts:336）—— **老用户不会受影响**，新用户默认看到 P0 + 战略要地的"清爽视图"，需要新闻时打开即可。
>
> **预期收益**：默认视图从 634 点降到 21 点（7 地缘 + 6 核设施 + 8 要地）—— **画面噪点降 96%**。
> **风险**：极低；老用户 localStorage 已记录 `news` 为开，继续生效。

#### 2.4.3 HIGHLIGHT 阈值上调（次高 ROI）

> **设计**：把"会触发常驻标签 + 光环"的强度阈值从 55 上调到 **70**（保持「中/高」严重度分界 `SEVERITY_THRESHOLD.high = 66` 的视觉一致性）。
>
> **改造点**：
> 1. `lib/mapData.ts:77` `HIGHLIGHT_THRESHOLD = 55 → 70`
> 2. 注意 `GlobePanel.tsx:323` 处的 `isFocus || (p.value ?? 0) >= HIGHLIGHT_THRESHOLD || p.isEvent` —— `isEvent` 不变（事件必带光环）
>
> **预期收益**：news_geo 当前 613 点中 intensity≥70 的 ≈ **110 个**（vs. 281 个 ≥55）—— 常驻标签数量降 **60%**，脉冲动画同步降噪。
> **风险**：低；2D/3D 共用同一阈值（共用 `mapData.HIGHLIGHT_THRESHOLD`），不会有视图漂移。

#### 2.4.4 视觉层级降噪

> **设计**：让"中"风险点（40 ≤ value < 70）只画**圆+外环**、**不画常驻标签**；标签只在 ≥70 时出现。
>
> 1. `GlobePanel.tsx:379`：`isFocus || value >= HIGHLIGHT_THRESHOLD` 改为 `isFocus || value >= HIGHLIGHT_THRESHOLD_HIGH`（新常量 70）
> 2. 同步 2D：目前 2D 没有常驻标签（d3 svg 无 html element），所以无需改——**2D 天然没有这个噪点**，问题只发生在 3D
>
> **预期收益**：globe 视图常驻标签数量从 ~285 → ~110，标签云消散。

#### 2.4.5 2D 弧线 & 缺失点

- 弧线动画 `fm-arc-flow` 是流动虚线（不是噪点），保留即可
- 缺失点（核设施 6 个，灰虚线菱形）保留当前处理（决策 C2-A）

## 3. 评估结论：图标 vs 画面乱，到底哪个是真问题？

| 反馈 | 真问题 | 解决方向 |
|------|--------|----------|
| 「图标依旧大」 | **3D ring 直径过大**（19.7–39.3px vs 2D 9–27px）| 收窄 3D ringMaxRadius 到 1.0+1.0w |
| 「内容看着乱」 | **默认图层涌 613 点 + 281 常驻标签互遮** | 默认关 news/conflict + HIGHLIGHT 70 + 聚合 |

→ 两件事都做，每个都只需改 1–3 行 + 1 个新函数。
