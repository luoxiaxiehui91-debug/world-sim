## D2 · 聚类（前端 bbox vs 后端预聚合）

### 问题
当某图层点位 > 500（尤其 FIRMS 热异常、ACLED 冲突事件）时，地图过密、视觉糊成一片。两种策略：

- **前端 bbox 聚合**：按视口实时聚合，每次 pan/zoom 重算
- **后端预聚合**：后端按 1°×1° 网格预算好 `cluster` + `count` 字段，前端只渲染

### 推荐 · **A · 折中（前端自写 bbox + 后端预留 reader）**

| 子项 | 做法 |
|------|------|
| 后端已就绪的图层 | 读 `cluster` 字段直接渲染 |
| 后端未就绪 + 点位 < 200 | 前端自写 1°×1° bbox 聚合（~80 行，零新依赖） |
| 后端未就绪 + 点位 ≥ 200 | 截断 + 状态条告警（与既有 `MAX_POINTS_PER_LAYER=2000` 护栏一致） |

**为什么不是 B/C**：
- **B 纯前端 supercluster** 需要新增 npm 包 → 违反 D5（不解锁依赖）
- **C 纯后端预聚合** 会卡半年以上（天枢排期未定）

### 选项
- [ ] **A** 折中（前端 bbox + 后端预留）—— **推荐**
- [ ] B 纯前端 supercluster（解锁 1 依赖）
- [ ] C 纯后端预聚合（等天枢）

### 推荐 · **A · 每类一文件**（已写进 `docs/天枢-fetcher×crucix-映射表-询问.md`）

| 维度 | 每类一文件 | 聚合大文件 |

## D4 · SSE 实时推送（做 vs 不做）

### 推荐 · **A · 不做**

当前数据源（GRV / FRED / news / nuclear）都是**日频或周频**，SSE 推送无意义。SSE 成本：
- 需后端配合增加"实时推送"运维面
- 需前端心跳 / 重连 / 状态恢复（+200 行）
- 需 EventSource 注册中心去重

开阳当前「拉一次 → 渲染」已足够覆盖。

### 选项
- [ ] **A** 不做 —— **推荐（已隐含采纳）**
- [ ] B 做（建议开阳 2.0 再议，触发条件：天枢支持实时 push）

## D5 · 解锁新前端依赖（Leaflet / MapLibre）

### 推荐 · **A · 不解锁**

当前 2D 用 d3-geo + topojson 手工实现，已支持基本 pan/zoom + 地区切换 + 点位渲染——功能足够。

Leaflet/MapLibre 与 d3-geo **互斥**，二选一会**推倒现有 2D**（~300+ 行）。MapLibre 用 WebGL 与 globe.gl 三栈并存可能冲突。**零依赖路线 A 已证明可走**（1.3.0–1.5.0 全部完成）。

### 选项
- [ ] **A** 不解锁 —— **推荐（路线 B 已暂停）**
- [ ] B 解锁 Leaflet（轻量，推倒现有 2D）
- [ ] C 解锁 MapLibre（WebGL 重型，与 globe.gl 三栈冲突风险）
