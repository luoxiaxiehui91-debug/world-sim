## 一、背景：我们在做什么，为什么来问你们

### 1.1 开阳正在做「对标 crucix 展示大屏」的复刻升级

开阳（前端操作面板）自立项起就写明了定位：**clean-room 复刻开源项目 `calesthio/Crucix` 的展示半边**（见 `DESIGN.md §2`）。此前开阳只复刻了其中很小一块——地图上只投影 GRV 一类风险点。本轮升级要把它推进到 crucix 的**多类别图层形态**（约 10 类指标图层 + 核设施监视 + 底部行情带）。

需要特别澄清的是，系统里同时存在**三个叫 "Crucix" 的东西**，容易混：

| # | 名称 | 是什么 | 与本文档的关系 |
|---|---|---|---|
| ① | `calesthio/Crucix` | 外部开源项目（Node/Express，端口 3117），就是我们要对标的那张大屏 | **本文档所有"crucix 源"均指它 README 里列的 27 个采集源** |
| ② | 开阳 kaiyang | 我们自己，复刻它的展示半边（React + globe.gl，全中文 UI） | 本文档的提出方 |
| ③ | 天枢的 "Crucix新闻" fetcher | 你们已用 Python 重实现的 crucix 新闻采集器，产出 `news_export.json` 里 `source:"Crucix新闻"` 的条目 | 已在跑，是本文档 §4 第 10 项要小改的对象 |

> 也就是说：**①的采集半边，本就应该由天枢逐个 Python 重实现**——③ 已经是其中一个成功案例。我们来问的，就是**除了 ③ 之外，①的其余源你们做了多少**。

### 1.2 开阳侧 P0 已经完工，现在卡在"不知道后端有什么"

前端不阻塞于后端的部分，我们已经全部做完并通过 QA（当前版本 `1.2.0`）：

| 已交付 | 内容 |
|---|---|
| **分类图层地基** | `RiskPoint.category` 枚举（13 类）+ 按类别着色 + 类别图例 + 逐类显隐开关，3D 地球与 2D 平面图同步 |
| **核设施图层 + 核设施监视面板** | 6 站静态种子坐标 + 菱形符号；**读数一律显示「—」**（前端绝不编造读数），等你们给真实读数 |
| **缺失降级** | 任一 feed 缺失 / 空数组 ⇒ 该图层不渲染 + 状态条告警，**不白屏** |

**卡点很明确**：剩下的 10 个图层、底部行情带、新闻上图，**全部是"后端有数据才有得画"**。我们现在完全不知道天枢侧哪些采集源已经存在。

### 1.3 我们想避免的两件事

1. **重复建设**——你们可能早就有等价 fetcher（比如地震、GDELT 已经在跑），我们却按"完全没有"去排期，白白拖两周；
2. **盲目排期**——把"其实要从零对接 ACLED / NASA FIRMS"的活儿排进近期迭代，到时候交不出来。

所以我们只要一份对照表，不要你们现在就动手开发。

### 1.4 开阳的两条铁律（涉及你们的工作量，请知悉）

- **开阳永不自连任何第三方数据源**（Yahoo / FRED / GDELT / OpenSky / ACLED 等一律排除）。凡是需要外网取数的，**必须由天枢代取并落盘为契约文件**，开阳只读文件。这条没有例外——所以下面第 13 项「市场行情」哪怕只是几个报价，也得走你们。
- **开阳只发令、后端执行**。开阳不实现任何采集 / 清洗 / 领域判断逻辑（例如辐射读数的告警阈值分级，应由你们在 feed 里给 `level`，而不是我们前端拍脑袋定）。

## 五、统一要求（所有新 feed 无例外）

无论哪一项，只要落地，都请满足下面 5 条——这是开阳的扩展标准，满足了我们就能"只加一处登记"接入，不用改渲染代码：

| # | 要求 | 说明 |
|:--:|---|---|
| 1 | **在开阳 `src/config/dataSources.ts` 的 `FEEDS` 登记一项** | 这一步是**开阳侧做**，不用你们操心。列在这里是让你们知道：我们接入成本很低，只要文件名和字段稳定 |
| 2 | **在 `DATA_CONTRACT.md` 补字段定义** | 由开阳维护，但需要你们把字段清单给全（含类型、必填与否、单位） |
| 3 | **携带 `schema_version`** | 首版填 `"1.0"`；**breaking change 必须 bump**。开阳读取层会比对版本并在状态条告警 |
| 4 | **点位类 feed 必须带 `lat` / `lng`** | **统一小数 4 位**（≈11m 精度，够用）。非有限数或超出 ±90 / ±180 的记录，开阳会整条丢弃而不是画到 (0,0) |
| 5 | **支持空数组 / 文件缺失** | 空数组是**合法业务态**（如"今日 0 起冲突事件"），不是错误。开阳按铁律降级：图层不渲染 + 面板显示「数据缺失」+ 状态条告警，**绝不白屏** |

补充两条口径约定：

- **文件粒度**：我们倾向 **每类一个文件**（与你们的 fetcher 一一对应），而不是一个聚合大文件——这样单类采集失败只影响单个图层，不会拖垮整张图。若你们有相反意见请提。
- **路径**：一律相对 data 根，不要绝对路径。开阳侧靠只读挂载 + `DATA_BASE_URL` 指向，**代码里禁止出现任何 NAS / SMB 绝对路径**。
