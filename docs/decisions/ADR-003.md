# ADR-003: PG-only 写路径与 SQLite 退役（WORLDSIM_SQLITE_OFF + P6 删库）

## Status
Accepted (2026-08-13)

## Background
读路径已全切 PG（ADR-002），但写路径仍"SQLite 主写 + PG 旁路双写"：
- news_db 写函数依赖 SQLite lastrowid 透传 id 给 PG upsert（主键策略）；
- synthesis_log 写路径（_write_log / cmd_silence / Live UPDATE）P5 前仍在写 SQLite；
- forecast_tracker / tianji_db / narrative_processor 写路径同理（P6 前置待办）。
P6 要物理删除 3 个 SQLite，必须先让写路径脱离 SQLite，否则删库后 `sqlite3.connect` 自动重建复生。

## Decision
1. **开关**：`WORLDSIM_SQLITE_OFF=1`（默认关=双写现状，线上零变化；开=PG 主写）。注入运行区
   docker-compose `environment:`（git 版被 rsync exclude）+ `docker compose up -d`（restart 不重载 env）。
2. **PG 主写改造**（开关分支）：news_db 6 写函数（write_scan_context/insert_articles/tag_articles/
   insert_signal_episode/link_episode_articles/prune_old_articles）——id 用 `_next_id`（PG MAX+1，
   单容器顺序写无并发竞争）、url/content_hash 查重与 pub_ctx 走 PG、删老文走 delete_news_articles；
   synthesis_log 写路径（_write_log/cmd_silence/Live UPDATE）——`_next_id` + upsert/update PG。
   get_trigger_titles（news_db 内残留 SQLite 读）直接切 PG。
3. **冻结 marker**：`data/.sqlite_frozen_at`（epoch）标记"SQLite 自此刻冻结"；探针 dualwrite 加 PG-only
   分支（有 marker → 验证 PG 五表健康 + SQLite mtime 不再增长），避免 SQLite 停写后 count 差误报 CRIT。
4. **P6 删库**：观察窗（12-24h）后 `bash 核心代码/delete_sqlite_e0c.sh`——门禁（marker/env=1/探针 OK/
   P4 备份存在）→ 快照 backups/e0c-p6-<ts>/ → rm news.db/forecast_tracker.db/narrative.db + 僵尸
   tianji.db（0 字节）。**P6 前置**：forecast/tianji/narrative 写路径补 PG-only（否则 forecast_tracker.db
   复生；读全 PG 无功能影响）。
5. **回滚**：去 compose env + rm marker + up -d 即回双写；备份在 backups/e0c-p4-20260813/。

## Consequences
- 正面：PG 单写单读（SSoT 彻底）；SQLite 退役省双写开销；探针 PG-only 语义清晰。
- 负面：PG 可用性成为唯一依赖（探针兜底 + ntfy 告警）；P6 前 forecast/tianji/narrative 写路径
  PG-only 改造未完（已列 task #67 前置）。
- 坑（固化）：函数内 `from X import f` 局部名 UnboundLocalError → `import X as _x`；psycopg 空元组参数
  也扫描 `%` → 无参 `execute(sql)`；scan_contexts.data_quality 是 text 列非 jsonb。
