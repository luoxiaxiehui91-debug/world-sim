# ADR-002: E0-C 读路径统一 PG（pg_read 只读层 + 14 reader 切换）

## Status
Accepted (2026-08-13)

## Background
P0-1 修复后 PG 数据完整（五表零差集），但 ~14 个模块仍直读 SQLite
（news.db / forecast_tracker.db），PG 虽双写却非权威读源（审计 P2-12）。
读路径不切 PG，删 SQLite 无从谈起；且 SQLite 直读点分散（每模块各自 sqlite3.connect + 内联 SQL）。

## Decision
1. 新建 `pg_read.py` 只读层：worldsim_app SELECT-only；自定义 `_Row` 行工厂等价 sqlite3.Row
   （`row["col"]` 与 `row[0]` 双访问）；**行边界归一化**（datetime→UTC 文本 `YYYY-MM-DDTHH:MM:SS`、
   Decimal→float、bool→int、bytes→str）——否则 consumer 的 `r[1][:10]` 切片会崩（实证 TypeError）；
   每次 connect 新建连接（不缓存，避免 `with c:` 关共享连接）；search_path=news,forecast,tianji,public；
   DML 兼容（row_factory description=None 不崩）。
2. 14 个 reader 全切 PG（news_exporter/ntfy/geo_risk/grv/daily_narrative/detector/tracker/
   signal_synthesizer/observability/web_server/forecast_tracker/tianji_db/narrative_processor）。
3. 双读校验台 `verify_reads_e0c.py`（27 查询对 + 7 全量对账）验证 SQL 移植语义等价；PG-only 模式下
   退化为 PG 健康检查（SQLite 冻结，等值不再适用）。
4. 方言规则（固化，可复用）：`",".join(["%s"]*N)`（勿用 `"%s"*N` 字符级 join）；psycopg 带参时字面 `%`
   须 `%%`；PG 禁 DISTINCT+ORDER BY 非 select 列 → `GROUP BY title ORDER BY MAX(ts)`；`DATE(x)`→`x::date`；
   `datetime('now','-24 hours')`→`NOW()-INTERVAL`；`sqlite_master`→information_schema；并列时间戳 LIMIT
   tie-break 子集差异合法（窗口全集一致）；P0-2 遗留 8h skew 容忍（PG 正确）。

## Consequences
- 正面：读全 PG，SQLite 降为纯写端伴读；observability 统计顺带修复（log_time/resonance_ok 列本不存在）。
- 负面：方言坑已踩并记录（见上）；LIMIT 边界 tie-break 与 SQLite 历史顺序可能不同（均合法）。
- 前置：P0-1（PG 数据完整）——已满足。
