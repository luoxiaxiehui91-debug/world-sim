# ADR-001: worldsim-pg 统一采集库（DB-first 地基）

## Status
Accepted (2026-08-12)

## Background
采集信息散落多份 SQLite（news.db / forecast_tracker.db / narrative.db / tianji.db 僵尸）与 CSV，
多副本漂移风险（P0-1 双写静默丢数即为实证：pg 比 SQLite 少 134 行且无对账自愈）。
下游（天璇仿真 / 开阳展示）需要一个统一权威源，避免"同一事实多份真相"。

## Decision
建立独立 PostgreSQL 容器 `worldsim-pg`（pgvector:pg16，NAS 侧 127.0.0.1:5434），
`news / forecast / tianji / rag / indicators` 五 schema 统一收口（B0 迁 news.db+forecast / D0 迁 chroma→pgvector）。
**新数据源禁止建独立 flat-file 契约**，一律复用 contracts.py/I1，schema PG-portable。
迁移锁序：A0 → A0.5 → C1 → A1-min → B1（双写证通）→ C0（加权）→ B0（迁库）→ D0（pgvector）→ E0（应用整合）。
迁移期 SQLite 保留为"只读伴读/双写目标"，读路径逐步迁 PG（见 ADR-002）。

## Consequences
- 正面：单库权威（SSoT）；备份/查询/跨表 JOIN 统一；探针可对账。
- 负面：迁移期双写成本；PG 可用性成为依赖（WORLDSIM_APP_PW / worldsim_default 网）；worldsim_app 非超户（CREATE EXTENSION 须 admin 装）。
- 后续：PG 数据完整后 SQLite 退役（ADR-003）。
