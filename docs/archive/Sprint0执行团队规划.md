## 0. 为什么先规划（不直接开执行团队）
- 评审刚收尾，待执行总量 = I1 契约 + probit + A1 回填 + A2 GED ETL + A3a 设计 + B1 crucix 盘点(+B2) + 天璇周报。若塞给少数 agent，单员超载、职责交叉 → 返工。
- 评审已定「并发安全三件套」+「核心文件独占令牌」——团队组织必须把它们落到 **“谁持有令牌、谁只新增”** 的层面，否则多 agent 并行 = 静默覆盖（pit⑥ ImportError→DATA_DIR 落非持久卷、rsync 整目录回滚）。
- 故：先出蓝图 → 总监认可 → TeamCreate `worldsim-sprint0-exec` → 按波次激活。

## 1. 团队组织架构
- **单一执行总团队** `worldsim-sprint0-exec`：共享 task list，总监（luoxi）统一看板；成员按波次激活，闲置不干扰。
- 角色成员（按 SOP 铁律5，`subagent_type` 用软件角色英文名，**禁中文名**）：
  - `software-product-manager`（PM）：范围钉死、验收清单协调、周报机制常设
  - `software-architect`（架构）：I1 契约、A3a 设计、并发隔离方案、设计评审
  - `software-engineer`（核心工程）：probit 实现 + A1 回填 —— **持 scheduler.py / fetcher_base.py 独占令牌**
  - `software-engineer`（ETL 工程）：A2 GED ETL —— 纯新文件 `etl_ged.py`，隔离最好，可与核心工程并行
  - `software-qa-engineer`（QA）：所有交付独立回归 + 两道静态闸（import 白名单 / 单文件 bind mount 扫描）
- 切片理由：工程切两员，避免一人扛 A2(2–3 人日) + probit(0.5) + A1(0.5–1)；QA 单员（回归串行触发即可），若波次并行多可补一名 QA。

## 3. 波次计划与依赖
- **波次一（设计/调研，零风险，可并行）**：I1 设计(架构+PM)、B1+B2(调研)、A2 ETL(ETL 工程)、A3a 设计(架构)。全纯新文件/只读，不碰 NAS 核心。
- **波次二（实现/止血，独占令牌串行）**：probit(核心工程) → A1(核心工程)。核心文件同段仅核心工程一人改。
- **波次三（等 D1）**：A3a 实现。
- **周报**：PM 常设，跨波次（防演示光环掩盖天璇 0%）。

## 4. 并发隔离落到团队（硬卡点）
- **独占令牌**：核心工程持有 `scheduler.py` / `fetcher_base.py` 令牌；波次二期间其余成员禁改这两文件，只新增。
- **ETL 工程**只碰 `etl_ged.py`（新文件），与核心工程无冲突，可与波次二并行。
- **部署通道统一**（待拍板选 scp+基线校验 或 rsync+校验，禁混用）；**NAS git init + 落地闸**（cp 前 sha256/md5 基线比对 + .bak + compileall + import smoke + `DATA_DIR==/workspace/data` 断言）为所有落 NAS 动作卡点。

## 5. 总监闸门（你只在这现身）
- **D1** = A3a 设计 review + `sim_trigger` 写侧协议拍板（决定 A3a 能否实现、A3b 是否启动）。
- **D2** = crucix 退场节奏（基于 B1 清单）。
- 其余 agent 之间自流转，不烦总监。

## 6. 开团队前置条件（建议拍板顺序）
- **可先写 SOP、不阻塞设计**：部署通道(2)、NAS git init(3)、静态闸固化 SOP(5) —— 这三条决定并发三件套最终写法，不开团队也能先固化。
- **设计阶段(波次一)不依赖拍板**，可先开。
- **铁律4 冲突(6)**（禁互连 vs 常态互连）决定 SOP 成员互连条款，建议与团队组织一并定。
- 天璇起轨 vs 仅周报(1)、D1/D2 命名(7) 为非阻塞，随时补。

## 7. 与 SOP 模式契合
- 单人总监（luoxi，不写码）+ 多角色 agent 常态辅助。
- 成员 `subagent_type` 必须英文软件角色 ID（SOP 铁律5）。
- 铁律4（禁互连）待拍板改，确认常态互连后，成员可直接协作（仍经主理人汇编递总监）。
