## 系统背景（精简，详見 `14_新session提示词_架构论证.md` / `16_世界推演系统_架构总文档_v1.0.md`）

跑在个人 NAS 上的宏观地缘推演系统。核心目标：给定不完整的、有噪声的观测信号，对未来状态做有置信度、可被证伪的预测，并通过验证不断校准自身。
- 观测层天枢（macro-scan v3.7.0）：22 源 → GRV 11 维 → LLM 日报，每日常驻。
- 推演层天璇（macro-sim v2.0.10）：GRV 触发，B 历史相似度 + A LLM 修正，Agent 动态激活。
- 校验层天玑（tianji_db / tianji_verifier）：存档预测 + 推理溯源 + 月度 Brier/BSS 验证 + 权重建议。
- 审批层玉衡（weight_matrix）：人工接受 / 观察 / 拒绝，写回权重矩阵。
- **冲突预测对应**：天璇地缘路径（事件序列 + 概率，人工验证）+ 天玑 Brier 验证。B1/B2/B4 直接对标这两层；B2 的 Brier 校准逻辑可直接校正天玑现有"只 Brier/BSS 缺迭代闭环"的短板（见对标 doc D1）。

## 方法论（与财经线同模板，务必照做）

1. **先读本地三份文档**（索引 + 对标 doc + 财经两篇报告），它们已含对标结论；外部项目是用来"深挖机制 / 验证结论"的，不是起点。
2. **一手来源校准**：Fed / 学术官网多为 JS 渲染，WebFetch 常只抓到导航 / 404（财经线已踩过坑）。改走：官方 working paper / FAQ / 代码仓库 + Google Scholar / arXiv 一手论文。WebSearch 摘要**不可作权威**，必须摸到原始公式 / 系数。
3. **每个项目产出结构**（固定）：
   - 机制原理（状态空间 / 公式 / 估计方法，越细越好）
   - 已知局限（决定我们"怎么用"而非"照搬"）
   - 映射到我们 L0–L5 哪层（重点：冲突预测对应天璇地缘路径 + 天玑 Brier 验证；B2 的 Brier 校准直接对标天玑）
   - 后续可借用点（非代码，列"可借鉴的方法论外壳 / 字段 / 流程"）
4. **分批产出**：建议 B1/B2/B4 一批（冲突预测核心），B3/B5/B11 一批（紧张度 / GDELT 同级），B6–B10 一批（综合指标 + 数据工程）。每批一篇同深度报告，结尾只留"后续可借用"标注。
5. **数据资产校验**：B4 用 NAS 上 GED v26.1 实测字段分布、与 GDELT 弱信号对比，验证我们现有冲突信号链路（narrative_processor 的 11 维叙事桶 / GDELT 三步法）。
