## 〇、结论先行（给实施 session 的 TL;DR）

1. **B3 World Tension Meter（WTM）** —— 最值钱的是它的**「慢变量单列不并入每日分」纪律**：每日紧张指数 = 冲突25%·能源20%·贸易20%·金融20%·媒体15%（0–100 归一化、每日双发、永久账本），而「油价/VIX/收益率/活跃冲突数」等**结构性风险监视器单列、每周更新、不进每日分**。这正好治对标 doc 指出的「GRV 与慢变量拆分有雏形但无 WTM 那种纪律」的短板——我们慢变量应严格单列、不并入日更快变量。
2. **B5 ACLED** —— **已放弃**（普通邮箱无可用 API 层）。机制上是「实时、地理编码的战斗/爆炸/针对平民暴力/抗议 + 伤亡」事件源，与 UCDP GED 同类但需注册邮箱 API key。ViEWS / War Monitor 把它当输入；我们因无法获取 API 层，已用免费 CC BY 4.0 的 UCDP GED 替代。本批仅作「为何选 GED 弃 ACLED」的对照锚点。
3. **B11 GDELT / GKG** —— **我们已在用**（weak_signal 金融 tone）。一手结构确认：Event DB 2.0（61 字段，CAMEO 四元组 `Actor1—Event—Actor2` + QuadClass + GoldsteinScale(−10~+10) + AvgTone(−100~+100)，15 分钟更新）；GKG 2.0（27 字段，V2Themes/V2Locations/V2Tone/GCAM 2300+ 情绪维度、65 语言实时翻译，Mentions 表带 **Confidence** 过滤）。**可借用点**：我们的 `narrative_processor` 目前只数 tone，应升级到消费 GKG 的 V2Themes/V2Tone/GCAM + 用 Confidence 过滤噪声（直接治 weak_signal→narrative 衰减）。

## 一、B3 · World Tension Meter（WTM）

### 1.1 它解决什么
把全球「宏观风险温度」合成一个**每日可读的紧张指数**，并另设**结构性风险监视器**单列慢指标。是「综合指标 + 慢变量纪律」的活样板。

### 1.2 方法论（一手来源：WTM 官网实时页 + 本地对标 doc §2.1）
- **每日紧张指数（Tension Index）**：综合 **冲突 / 能源 / 贸易 / 金融 / 媒体** 五维，按权重合成：
  ```
  紧张指数 = 冲突·25% + 能源·20% + 贸易·20% + 金融·20% + 媒体·15%
  ```
  每信号按自身**多年历史归一化到 0–100**（读数 70 = 今日在过去五年真正排前三分之一，而非关键词触发）。
- **发布节奏（活页确认）**：完整分析**每日两次**（00:00 / 12:00 UTC）；市场数据每 10 分钟刷新；每日数值追加至**永久账本且不可更改**（point-in-time 纪律）。
- **结构性风险监视器（核心纪律）**：把**慢结构指标**（油价 / VIX / 收益率曲线 / 活跃冲突数）**单列、每周更新、不进每日分**——避免慢变量污染日更快变量的读数。
- 四大「worlds」信号面板：冲突监控 / 大宗商品市场 / 金融压力 / 全球媒体覆盖（与五维权重一致）。

### 1.3 已知局限
- **权重是经验设定**：25/20/20/20/15 为作者经验权重，非数据驱动推导（对标 OECD 综合指标「任意权重」反模式，但 WTM 透明列明）。
- **依赖新闻覆盖**：媒体/冲突维本质来自 GDELT/ACLED，受媒体盲区与源偏置影响（与 GDELT 同源缺陷）。
- **描述非预测**：WTM 明确自身是态势感知层，不作预测或权威伤亡记录（活页局限性声明）。

### 1.4 映射到我们 L 哪层
- **GRV 合成 + 慢变量纪律（直接对标 D2）**：对标 doc §2.1 明确指出「GRV 与慢变量的拆分有雏形但无 WTM 那种'慢变量单列不并入'的纪律」。WTM 是这套纪律的范本——我们的 UCRI/GCI 慢变量应**严格单列、不并入日更快变量 GRV**。
- **L5 叙事 / 综合指标（M6 同思路）**：五维加权合成 + 0–100 归一化，可借到我们 GRV 11 维合成的展示与告警阈值设计。

### 1.5 后续可借用点（非代码）
- **慢变量单列纪律**：把慢变量（UCRI/GCI/油价/VIX/收益率）作为独立「结构风险监视器」面板，**每周更新、不参与每日 GRV 合成**，根治「快慢变量互相污染」。
- **0–100 相对历史归一化**：GRV/紧张度读数改用「相对自身 N 年历史的分位」而非绝对数，读数更直观（如「今日紧张度处于过去 5 年 90 分位」）。
- **永久不可变账本**：每日快照追加不覆盖（呼应 ALFRED vintage 纪律 M6），未来回测用当时已知值。

## 二、B5 · ACLED（Armed Conflict Location & Event Data）

### 2.1 它解决什么
实时、地理编码的**政治暴力与抗议事件**数据库：战斗、爆炸、针对平民的暴力、抗议，含地点、行为体、伤亡数。是事件级冲突源，与 UCDP GED 同类但更偏实时。

### 2.2 方法论（一手来源：ACLED 官网 + 本地索引 §二 B 段）
- 事件级编码：每次事件带 `event_type`（battles/protests/violence against civilians/explosions…）、`admin1/admin2`、经纬度、`fatalities`、`actors`。
- **获取方式**：需**注册邮箱申请 API key**（免费但需账号层），实时/历史 API 拉取。
- 被 ViEWS、War Monitor 等作为冲突输入源。

### 2.3 为何放弃（本系统角度）
- **普通邮箱无可用层**：本地索引 §二 B5 明确标注「**已放弃：普通邮箱无可用层，仅作对照**」。我们 NAS 环境用的普通邮箱无法申请到可用的 ACLED API 层，故不接入。
- **已被 UCDP GED 替代**：我们已落 GED v26.1（CC BY 4.0、免费、417,968 事件、含 deaths/地理/行为体），覆盖同类需求且零授权摩擦。

### 2.4 已知局限（作对照）
- 实时性强但**编码口径与 UCDP 不同**（ACLED 含暴乱/抗议，UCDP 排除且伤亡核实更严），二者不可混用（War Monitor 明确不混用不兼容数据集）。
- 依赖注册 API，源覆盖有盲区。

### 2.5 映射到我们 L 哪层
- **仅作对照锚点**：印证「选 UCDP GED 弃 ACLED」的决策合理性；不进 GRV/天璇契约。
- 若未来有合规邮箱层，可作 GED 的**实时补充**（GED 滞后数周，ACLED 实时），但当前不纳入。

### 2.6 可借用点
- 无（已放弃）。仅记录：GED（免费、历史深）与 ACLED（实时、需授权）是冲突事件源的两极，我们取免费历史极。

## 三、B11 · GDELT / GKG（Global Database of Events, Language and Tone）

### 3.1 它解决什么
全球新闻事件的**实时量化语料库**（GDELT 2.0 每 15 分钟更新、65 语言实时翻译）。两大库：**Event Database**（个体事件，CAMEO 编码）+ **GKG**（个体文章，主题/实体/语调）。我们已用其 weak_signal 金融 tone。

### 3.2 方法论（一手来源：GDELT Event Codebook V2.0 / GKG Codebook V2.1 / deepwiki gdeltPyR / ONS GDELT 附录）
**Event Database 2.0（61 字段）：**
- 结构 = CAMEO 扩展四元组 `Actor1Code — EventCode — Actor2Code`，附加地理/时间/语调。
- 关键字段：
  - `EventCode / EventBaseCode / EventRootCode`：CAMEO 4 层、310 类（从「军事撤退」到「族裔清洗」）。
  - **`QuadClass`**：4 大类——口头合作 / 物质合作 / 口头冲突 / 物质冲突。
  - **`GoldsteinScale`**：事件对稳定性的**理论潜在影响** −10（极负面）~ +10（极正面），**仅由 EventCode 决定**（10 人与 1 万人抗议同分——已知局限）。
  - **`AvgTone`**：报道该事件文章的平均语调 −100 ~ +100（多数文章 −10~+10，0 为中性）。
  - `NumMentions / NumSources / NumArticles`：15 分钟窗口内的提及/源/文章计数（即时反应强度）。
  - `ActionGeo_*`：事件地理（国家/ADM1/经纬度）。
- **GKG 2.0（27 字段）：**（记录「文章」而非「事件」）
  - `V2Themes`：文章主题（如 `ECON_INFLATION`、`ENV_CLIMATE`）。
  - `V2Locations / V2Persons / V2Organizations`：实体。
  - **`V2Tone`**：六维核心情绪（Positive/Negative/Polarity/…）。
  - **`GCAM`**：Global Content Analysis Measures——**2300+ 情绪/主题维度、原生 15 语言**评估（LIWC Anxiety、Lexicoder Positivity…）。
  - `Counts`：文中出现的数字（死亡数、经济数据…）。
- **Mentions 表**：追踪每次提及，含 **`Confidence`**（2.0 新增，0~100 提取置信度，可据此过滤灵敏度——取高 Confidence 得大事件、全流得破冰小事件）。
- **Translingual**：65 语言实时翻英，覆盖 98.4% 非英语监测量——**多语言覆盖是 GDELT 相对 ICEWS（偏英语）的关键优势**。

### 3.3 已知局限（严谨性警示，对标 doc §3.6 已列）
- **Goldstein 只看事件类型不看规模**：抗议规模不影响分，需另用 NumMentions/Counts 补规模。
- **Tone 受源偏置**：媒体盲区/西方源偏重，绝对语调不可全信，宜用相对历史分位。
- **采样不稳定、关键词敏感**：GDELT→宏观信号需严格统计检验（对标 doc 警示）。
- **弱信号→叙事衰减**：我们 macro-scan 的 weak_signal（日元87/标普69/USD68）密集但到终稿只剩三两句——GKG 的 V2Themes/GCAM 未被充分利用。

### 3.4 映射到我们 L 哪层
- **L5 叙事 / weak_signal（直接对标 D6 + M4）**：我们已抓 GDELT，当前只数 tone；应升级到消费 **GKG 的 V2Themes/V2Tone/GCAM + 用 Confidence 过滤噪声**（对标 doc A4.1④ 三步法：关键词→NN→国家月聚合→PCA-3→AR）。
- **天璇地缘事件原语（呼应 B1 ICEWS 三元组）**：GDELT Event 的 `Actor1—Event—Actor2` 与 ICEWS 三元组同构，是我们地缘路径的统一事件源。
- **与 GED 校验闭环（见 Batch 1 §四）**：GDELT 是 lead signal，GED 是暴力真相，二者 lead-lag 标定。

### 3.5 后续可借用点（非代码）
- **GKG 深度消费**：`narrative_processor` 从「数 tone」升级为「抽 V2Themes（主题）+ V2Tone（六维）+ GCAM（情绪维度）+ 实体（V2Persons/Orgs）」，喂 11 维叙事桶更密。
- **Confidence 过滤**：用 Mentions 表 `Confidence` 字段过滤弱信号噪声（治衰减），大事件取高 Confidence、早期破冰取全流。
- **多语言覆盖利用**：GDELT 65 语言实时翻译已帮我们跨过 ICEWS 的英语偏置，冲突信号链应显式纳入非英语源权重。
- **三步法 + PCA-3**：按对标 doc A4.1④ 升级 weak_signal → 国家×月聚合 → PCA 取 3 主成分 → 喂 AR，减衰减（M4）。
