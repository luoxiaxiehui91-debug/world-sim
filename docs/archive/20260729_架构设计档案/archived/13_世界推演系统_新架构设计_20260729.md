## 0. 系统本质

给定关于世界的不完整、有噪声、有延迟的观测信号，对未来状态做出**有置信度的、可被证伪的预测**，并通过验证结果不断校准系统自身。

**核心闭环：**

```
信息源
  ↓
天枢（状态估计）
  ↓ 异常触发
天璇（推演引擎）
  ↓ 输出预测
天玑（校验）
  ↓ 发现问题
玉衡（权重审批）
  ↓ 人工确认后
回到天枢（权重矩阵更新）
```

## 一、信息源

### 1.1 设计原则

信息源广度优先，覆盖所有可能影响世界状态的信号类别。**不靠删减信息源来控制噪声，靠权重矩阵过滤。**

同一批信息源被天枢和天璇同时使用，各自提取不同维度：
- 天枢提取量化信号（数字、时序）
- 天璇提取叙事信号（文本、语义）

### 1.2 当前信息源分类（22个）

继承现有天枢fetcher体系，不大改。详见`世界推演系统_信息源完整手册_20260729.md`。

### 1.3 待补充的三大类（⚠️ 工程实现待讨论）

| 类别 | 具体来源 | 优先级 |
|------|---------|--------|
| **叙事层** | Google Trends（pytrends）/ 扩展RSS语种（俄/阿/印地语媒体）| 高 |
| **军事层** | SIPRI年度数据 / 防务类RSS（Defense News/Breaking Defense）/ NTI核态势 | 中 |
| **供应链实体层** | 纽约联储GSCPI / Freightos FBX / PMI交货期子项（FRED已有）| 高 |

### 1.4 Crucix的定位与退出计划

- **当前**：继续使用，27个OSINT源+注入天枢LLM prompt，职责不变
- **近期**：删除Crucix内部EIA采集模块（与天枢重复）
- **长期退出**：Crucix是过渡方案，AGPL-3.0有版权风险
  - 退出触发条件：天枢fetcher覆盖Crucix所有核心信号（gscpi/nuke/sdr/air）后才剔除
  - 退出后：开阳直接读天枢数据

## 二、天枢（观测层）

### 2.1 核心职责

每日常驻运行，做两件事：

**① 参数运算 → 状态向量**

从量化信息源提取数值信号，输出世界状态向量。

状态向量分两层：

| 层级 | 变量类型 | 更新频率 | 示例 |
|------|---------|---------|------|
| 慢变量 | 结构性背景 | 月频 | 中美博弈强度、通胀体制、地缘格局 |
| 快变量 | 实时信号 | 日/小时频 | GRV 11维、市场情绪、事件冲击 |

慢变量决定快变量的基准分布，**快变量偏离慢变量基准**触发天璇推演。

**关键改进**：GRV每个维度从标量改为**带不确定度区间的分布**（如：台海52.7±8，95%置信区间），不只是一个数字。

**② 叙事预处理 → 叙事快照**

从文本信息源提取叙事信号，按主题聚合成文本块，**不做标签化压缩，保留原始语义**。

天璇激活时按触发维度按需读取相关文本块，不全量读。

### 2.2 权重结构

不是全局权重，而是**权重矩阵**：

```
              台海冲突  通胀  金融危机  政治动荡  ...
制裁信号        0.8    0.3    0.6      0.4
GDELT事件       0.6    0.2    0.3      0.7
FRED利率        0.2    0.9    0.8      0.2
军事RSS         0.7    0.1    0.2      0.5
...
```

- 行 = 信息源类别
- 列 = 预测目标类型
- 冷启动：人工经验填入
- 后续：天玑校准结果通过玉衡审批后更新

### 2.3 继承现有代码

天枢fetcher体系大部分继承，主要改动：
- GRV从标量改为带不确定度的分布
- 新增叙事预处理模块
- 权重从硬编码常量改为读取`grv_weights.yaml`（玉衡写回的目标）

## 三、天璇（推演引擎）

> **现有macro-sim基本重写。** agent定义、迭代机制、输出格式全部重新设计。

### 3.1 触发机制

保持现有成本结构：
- 天枢：每日常驻，便宜
- 天璇：快变量偏离慢变量基准触发，按需激活

### 3.2 输入

天璇激活时同时读取两类输入：
```
① 数值状态：GRV状态向量 + FRED关键指标（结构化）
② 叙事上下文：触发维度相关的文本块（非结构化）
```

### 3.3 推演引擎：B+A组合

**B（历史相似度匹配）先跑：**
- 在知识库里找当前状态最相似的历史时期
- 给出"历史上这种情况后来怎么发展"作为基础参考路径
- 概率来自历史频率，有数据基础

**A（LLM推理）后跑：**
- 判断当前与历史的关键差异
- 在B的路径基础上做修正，补充历史未覆盖的新变量
- LLM只做边际调整，不重写概率（⚠️ 调整幅度上限待详细讨论，见P1）

**C（参数化转移矩阵）：长期演进，积累足够数据后引入。**

### 3.4 Agent设计

**定义**：agent = 真实行为主体，不是分析视角。

| 主体类型 | 示例 |
|---------|------|
| 国家主体 | 美国、中国、俄罗斯、欧盟、日本 |
| 机构主体 | 美联储、OPEC、IMF、WTO |
| 市场主体 | 债券市场、股票市场、外汇市场 |
| 社会主体 | 舆论/媒体、民众情绪 |

**关键原则**：
- 每个agent读取**全域信息**（数值状态+叙事上下文），基于自身利益+约束条件决策
- agent不锁死在单一视角——央行也要考虑地缘、政治、社会因素
- 数量不固定，**按触发情景动态激活相关主体子集**
- agent之间相互影响，迭代推演（非同时输出）

### 3.5 推演迭代机制

**校准阶段：**
- 用历史数据回放
- 跑到状态向量与历史真实数据误差收敛为止
- 不固定轮数，收敛条件驱动
- 校准阶段为内部状态，不输出给用户

**推演阶段：**
- 满足以下任一条件停止：
  - 概率树过于发散（所有路径概率低于阈值）
  - 达到时间边界
  - 状态收敛（所有路径指向同一稳定状态）

**时间边界动态判断（按触发情景类型）：**

| 情景类型 | 时间边界 |
|---------|---------|
| 金融市场冲击 | 周级 |
| 地缘军事事件 | 月级 |
| 结构性地缘转变 | 年级 |

### 3.6 输出格式（三种并行）

**① 地缘路径（人工验证）**
- 事件序列 + 各事件概率
- 示例："台海演习升级（40%）→ 经济封锁（15%）→ 全球供应链重组（8%）"

**② 量化传导（自动验证）**
- 条件概率 + 具体指标
- 示例："若封锁发生：3个月内半导体ETF跌15%，概率65%"

**③ 叙事输出（人类可读）**
- 独立生成，不是①②的翻译
- 基于所有agent行为，将最可能发生的结果串联，写清整个发展过程
- 有温度、有逻辑连贯性的自然语言叙事

## 四、天玑（校验层）

> **全新建设，现有系统完全缺失此闭环。**

### 4.1 核心职责

存档预测 → 到期验证 → 反哺权重矩阵建议

### 4.2 存档结构（三张表）

**表一：预测主张**

| 字段 | 说明 |
|------|------|
| prediction_id | 唯一ID |
| created_at | 预测生成时间 |
| due_at | 验证截止时间 |
| type | 量化指标 / 地缘事件 |
| content | 预测内容（自然语言） |
| target_metric | 验证用具体指标（FRED序列/GRV维度） |
| target_direction | 方向（涨/跌/超过某值） |
| target_threshold | 具体数值 |
| probability | 预测概率 |
| time_horizon | 时间跨度类型（周级/月级/年级） |
| status | 待验证/已验证/人工确认中 |
| brier_score | 验证后填入 |

**表二：推理溯源**

| 字段 | 说明 |
|------|------|
| prediction_id | 关联预测主张 |
| agent_id | 哪个agent产出了这条预测 |
| input_signals | 当时输入的信号列表（信号名+值+权重） |
| historical_match | B阶段匹配到的历史时期 |
| confidence_basis | 概率来自历史频率还是LLM调整 |
| llm_adjustment | LLM调整了多少（±X%） |

**表三：权重更新日志**

| 字段 | 说明 |
|------|------|
| update_id | 唯一ID |
| updated_at | 更新时间 |
| prediction_id | 触发本次更新的预测 |
| signal_name | 被更新的信号 |
| target_type | 被更新的预测目标类型 |
| weight_before / weight_after | 更新前后 |
| reason | 自动校准 / 人工干预 |

### 4.3 验证流程

```
每月1日天玑自动跑
↓
查所有 due_at <= 今天 且 status=待验证 的预测
↓
量化预测：自动拉FRED/GRV历史数据 → 计算Brier分 → status=已验证
地缘预测：ntfy推送提醒人工确认 → 你回复发生了/没发生 → status=已验证
↓
触发反哺逻辑
```

### 4.4 反哺逻辑

```
拿到Brier分
↓
查推理溯源：这条预测用了哪些信号、哪个agent
↓
计算该信号在过去N条同类预测里的平均Brier分
↓
单条错了 → 不触发（样本太少，可能偶然）
连续N条同类信号+同类预测目标持续差
  → 生成降权建议 → 写入待审批文件 → 推送玉衡
```

**关键原则**：不自动写回任何参数，所有建议必须经玉衡人工审批。

## 五、玉衡（权重审批层）

> **全新建设。天玑发现问题，玉衡修复问题。**

### 5.1 核心原则

**任何参数变动必须经过人工确认，永远不自动写回。**

### 5.2 每条建议的展示内容

- 建议内容：哪个信号、哪类预测目标、权重从X改到Y
- 依据：过去N条相关预测的Brier分趋势
- 对比：同信号对其他预测目标的表现（区分"信号失效"还是"只对这类预测失效"）
- 历史参考：类似调整的历史案例和效果
- 置信度：基于多少条样本，置信度多少

### 5.3 三个操作选项

| 操作 | 效果 |
|------|------|
| **接受** | 立即写回权重矩阵 |
| **观察** | 再积累N条预测后重新评估 |
| **拒绝** | 记录原因，不修改 |

### 5.4 待深入论证（⚠️）

- 用户判断建议对错的依据如何建立
- 置信度阈值如何设定
- 长期积累后是否引入辅助决策机制
