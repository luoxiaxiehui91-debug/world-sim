## 风险按"是否阻塞 5 主层 + 2 横切架构落地"分类

### 必须立即缓解（Tier 0 必须完成，否则架构无法落地）

- **R1** 部署漂移——任何"5 主层"架构的前提是天枢稳定运行
- **R2** R08 在线 bug——产出假信号会让所有下游（含玉衡校准）都不可信

### 必须 Phase 1 缓解（否则 Phase 2 启动即崩塌）

- **R4** Crucix EIA 重复采集——划清职责边界是"实时信号总线"重定义的前提
- **R9** SMB 误读——任何 Tier 0/Tier 1 操作都可能因误读做出错误决策

### 必须 Phase 2 缓解（首次写回/解冻前必须就位）

- **R3** 校验开环继续存在——玉衡 V1 的成功取决于人工审批流程真的被执行
- **R7** 天玑 LLM 提取准确率——ledger 污染会让玉衡校准建议失真
- **R8** 玉衡校准写回错误——首次写回必须有影子模式 + 7 天观察

### 持续监控（长期）

- **R5** STAGING_MODE 误解冻——Phase 3 前只监控不解冻
- **R6** LLM 配额耗尽——T1-2 可观测性计数器 + 摇光告警
- **R10** 维护负担爆炸——neat-freak Skill 季度整理
- **R11** 玉衡通道无人使用——每月统计采纳率

## 风险与"不做清单"的对应

- ❌ **不做分布式**——缓解 R10（容器数恒定 4）

- ❌ **不做 7 层物理容器化**——缓解 R10（物理恒定 4 容器）
- ❌ **不做通用知识图谱**——缓解 R10（玉衡子能力已够用）
