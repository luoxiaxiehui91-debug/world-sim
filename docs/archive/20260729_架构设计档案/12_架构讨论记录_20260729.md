## 已确定的架构决策

### 1. 预测的两个层次
- **量化指标预测**（GRV、价格、利率）→ 自动验证，自动校准
- **地缘事件预测**（冲突、制裁、政治动荡）→ 人工验证，反查信号预测力

### 2. 状态空间分层
- **慢变量**（月频）：结构性背景——中美博弈强度、通胀体制、地缘格局
- **快变量**（日/小时频）：实时信号——GRV 11维、市场情绪、事件冲击
- 慢变量决定快变量的基准分布，快变量偏离基准触发推演

### 3. 两套计算逻辑（核心洞察）
天枢和天璇不是串行处理不同信息源，而是**同一批信息源各自提取不同维度**：
- **天枢**：从信息源中提取量化信号 → 参数运算 → 状态向量
- **天璇**：从信息源中提取叙事信号 → LLM推理 → 概率路径

### 4. 信息源处理方式
天枢每日常驻时做两件事：
- 参数运算 → GRV状态向量（带不确定度区间，不只是标量）
- 叙事预处理 → 按主题聚合文本块（不做标签化压缩，保留原始语义）

天璇激活时同时读取：
- 数值状态：GRV向量 + FRED关键指标（结构化）
- 叙事上下文：相关主题文本块（非结构化）

### 5. 推演引擎：B+A组合
- **B（历史相似度匹配）**：先跑，找历史最相似时期，给出基础参考路径
- **A（LLM推理）**：后跑，判断当前与历史的关键差异，在B的基础上修正
- **C（参数化转移矩阵）**：长期演进方向，积累足够数据后引入

### 6. 天璇输出格式（三种并行）
- **地缘路径**：事件序列 + 概率（人工验证）
- **量化传导**：条件概率 + 指标（自动验证）
- **叙事输出**：独立生成，基于所有agent行为，将最可能发生的结果串联，写清整个发展过程（不是结构化输出的翻译，是独立的人类可读叙事）

### 7. Agent设计原则
- **定义**：agent = 真实行为主体，不是分析视角
- **类型**：国家主体（美中俄欧日）/ 机构主体（美联储/OPEC/IMF）/ 市场主体（债券/股票/外汇）/ 社会主体（舆论/民众情绪）
- **输入**：每个agent读取全域信息（数值状态+叙事上下文），基于自身利益+约束条件决策
- **输出**：只输出"这个主体最可能采取什么行动"，不越界
- **数量**：不固定，按触发情景动态激活相关主体子集
- **交互**：agent之间相互影响，迭代推演（非同时输出）

### 8. 推演迭代机制
- **校准阶段**：用历史数据回放，跑到状态向量与历史真实数据误差收敛为止（不固定轮数）
- **推演阶段**：满足以下任一条件停止：
  - 概率树过于发散（所有路径概率低于某个阈值，继续推无意义）
  - 达到预设时间边界（根据触发情景类型动态判断，不固定）
  - 状态收敛（所有路径指向同一稳定状态）
- **时间边界动态判断**：
  - 金融市场冲击 → 周级
  - 地缘军事事件 → 月级
  - 结构性地缘转变 → 年级
- **原则**：收敛条件驱动，不是轮数驱动；推演轮数过多误差累积变成幻觉
- **输出**：校准阶段为内部状态不输出，推演阶段提取关键转折点整理成三种输出

### 7. 权重结构
不是全局权重，而是**权重矩阵**：
- 行 = 信息源类别
- 列 = 预测目标类型（台海冲突、通胀、金融危机、政治动荡…）
- 冷启动靠人工经验填，天玑校准后自动更新

### 9. Crucix的定位与退出计划
- **当前**：继续使用，稳定运行27个OSINT源+注入天枢LLM prompt
- **近期**：删除Crucix内部EIA采集模块（与天枢fetch_energy_eia.py重复）
- **长期**：Crucix是过渡方案，最终剔除
  - 原因：AGPL-3.0版权约束，长期有风险
  - 退出触发条件：天枢fetcher体系覆盖Crucix所有核心信号（gscpi/nuke/sdr/air）后才剔除，不提前动
  - 剔除后：开阳直接读天枢数据，不再依赖Crucix

## 待详细讨论的问题

### P1 概率生成逻辑（⚠️ 需要详细讨论）

**当前提议**：
- 概率只来自B（历史频率）——"历史上类似情况有X%发生了Y"，有数据基础
- A（LLM）只负责判断当前与历史的差异方向（上调/下调），不重写概率
- LLM调整幅度有上限（±15%），保证概率有历史锚定

**待讨论**：
- ±15%上限是否合理？如何确定？
- 历史样本不足时如何处理？
- 完全没有历史先例的新情景（如AI战争）怎么给概率？

### P2 叙事主题聚合的具体方式
- 按什么维度聚合文本块？
- 如何控制context长度不爆炸？
- 相关性判断逻辑（触发的是台海维度，只拉台海相关文本块）

### P3 信息源扩充方案
当前缺失的三大类：
- **叙事层**：Google Trends、扩展RSS语种（俄/阿/印地语媒体）
- **军事层**：SIPRI年度数据、防务类RSS、NTI核态势
- **供应链实体层**：纽约联储GSCPI、Freightos FBX、PMI交货期子项

### P4 慢变量的具体定义和测量方式
- 中美博弈强度怎么量化？
- 通胀体制如何判断当前处于哪个状态？

## 玉衡（权重审批层）设计

### 核心定位
天玑负责发现问题，玉衡负责修复问题。
**任何参数变动必须经过人工确认，永远不自动写回。**

### 展示内容
每条建议必须包含：
- 建议内容：哪个信号、哪类预测目标、权重从X改到Y
- 依据：过去N条相关预测的Brier分趋势
- 对比：同信号对其他预测目标的表现（区分"信号失效"还是"只对这类预测失效"）
- 历史参考：类似调整的历史案例和效果
- 置信度：基于多少条样本，置信度多少

### 三个操作选项
- **接受** → 立即写回权重矩阵
- **观察** → 再积累N条预测后重新评估
- **拒绝** → 记录原因，不修改

### 待深入讨论（⚠️ 需要大规模论证）
- 判断标准如何建立——用户凭什么判断建议对不对
- 置信度阈值如何设定
- 长期积累后是否引入辅助决策机制


### 存档结构（三张表）

**表一：预测主张**
- prediction_id / created_at / due_at / type（量化/地缘）
- content（自然语言）/ target_metric / target_direction / target_threshold / probability
- time_horizon（周级/月级/年级）/ status（待验证/已验证/人工确认中）/ brier_score

**表二：推理溯源**
- prediction_id / agent_id / input_signals（信号名+当时值+当时权重）
- historical_match（B阶段匹配的历史时期）
- confidence_basis（概率来自历史频率还是LLM调整）/ llm_adjustment（±X%）

**表三：权重更新日志**
- update_id / updated_at / prediction_id（触发来源）
- signal_name / target_type / weight_before / weight_after
- reason（自动校准/人工干预）

### 验证流程
- 每月1日自动跑一次
- 量化预测：自动拉FRED/GRV历史数据，计算Brier分
- 地缘预测：ntfy推送提醒人工确认（发生了/没发生）
- 验证完成后触发反哺

### 反哺逻辑
- 查推理溯源：这条预测用了哪些信号、哪个agent
- 计算该信号在过去N条同类预测里的平均Brier分
- **单条预测错了不触发更新**——样本太少可能是偶然
- 连续N条、同类信号、同类预测目标持续差 → 生成降权建议写入待审批文件
- 人工确认后才真正更新权重矩阵（不自动写回）
- N的初始值人工设定，积累数据后动态调整

## 开阳（展示层）设计

### 定位
- 独立建立，与Crucix彻底分开
- Crucix继续做OSINT信号采集+注入天枢LLM prompt，职责不变
- 开阳专门展示世界推演系统自有数据

### 目标展示内容
- 世界状态面板：慢变量+快变量（带不确定度）
- 推演面板：地缘路径+量化传导+叙事输出
- 天玑面板：历史准确率+待验证列表+人工确认入口
- 玉衡面板：待审批权重建议+操作入口

### 视觉目标
参考Crucix的展示风格（3D WebGL+玻璃拟态+实时刷新）

### 优先级
**暂不启动，当前以ntfy推送为主。**
后端模块（天璇重写/天玑/玉衡）建好后再分阶段接入。
