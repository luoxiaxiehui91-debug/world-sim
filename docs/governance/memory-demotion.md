## 1. 分层表

| 层 | 定义 / 权威 | 触发降级条件 | 降级动作 | 执行者 |
|----|-------------|--------------|----------|--------|
| **T1 设计权威** | 架构/设计决策（ADR、tianji-design、overview 架构图） | ①被 Confirmation 证伪 ②被新 ADR 取代 | 标 `superseded` 指向新真源，降为「历史记录」，不再参与活跃仲裁 | 负责人人工走 PR，AI 仅起草 diff |
| **T2 实时状态** | 当前状态快照（HANDOVER 状态块、INDEX 计数、README/AGENTS 版本行） | ①TTL 7 天未复验 ②任一验证命令失败 | 标 `as-of` 日期移入流水/归档，降为「历史快照」 | AI 自动执行（标 stale） |
| **T3 append-only** | 历史流水（CHANGELOG、operations、归档） | 历史条目被证伪 | 追加「更正」条目（**不删不改原文**） | AI 执行 |
| **MEMORY.md** | 红线 + 硬事实 | 红线**永不降级**；硬事实被证伪 | AI 修订 + 负责人复核，留更正记录 | AI + 负责人 |

**优先级**：冲突仲裁先于降级。任何降级动作前，先按方向 A 仲裁表（运行态 > 代码真源 > 文档/记忆）判定真源归属，再决定哪一层降级；不得直接凭记忆判文档过期。

## 2. 降级操作步骤

### 2.1 T1 superseded 标记格式（替换原文件头）

```markdown
> 状态：superseded
> 取代者：<新真源路径> @ commit <hash>
> 降级时间：YYYY-MM-DD HH:MM CST
> 降级原因：被 Confirmation 证伪（命令 <cmd>，实测 <值>）/ 被新 ADR 取代（<ADR 编号>）
> 历史价值：保留为设计演进记录，不再参与活跃真源仲裁
```

执行要求：走 PR，AI 只产出 diff 草稿，负责人 review 后合入；不得 AI 直接 push。

### 2.2 T2 as-of 快照迁移（AI 自动执行）

1. 原状态块首行加标记：`> as-of: YYYY-MM-DD HH:MM CST（已降级为历史快照，stale）`
2. 原内容整体复制到流水区/归档（`docs/archive/` 或本文档历史区），保留可追溯
3. 原位置只留一行指针：`> 当前状态：见 <新真源路径>（as-of 快照已归档）`
4. 跑第 3 节验证命令，确认新真源可读且数值一致，验证输出入 operations

### 2.3 T3 更正条目模板（只追加，不修改原文）

```markdown
- [更正 YYYY-MM-DD] 本条目此前声称「<原声称>」，实测为「<实测值>」
  （命令 <cmd>，as-of <时间>，commit <hash>）。原条目保留供审计，不再作为引用依据。
```

## 3. 验证：降级后如何确认新真源生效

降级动作本身必须被验证，否则降级也会成为新的漂移源。四条验证，全部通过才算降级完成：

1. **新真源可读性**：运行方向 C 注册表对应命令，期望值 = 新真源当前值，实测一致才生效。
2. **旧条目不再被引用**：grep 活跃文档（README/HANDOVER/AGENTS/INDEX/overview），确认无指向已降级条目的链接或裸数字；引用只指向新真源。
3. **快照完整性**：T2 归档文件存在且 mtime = 降级时刻；T3 更正条目数 = 证伪次数（可计数校验）。
4. **命令即证据**：验证输出记入 operations 流水，附 as-of 时间戳；验证命令一律走方向 C 注册表（verify.sh），禁手写临时命令；未绑定唯一部署通道的降级动作视为未完成（联动方向 D）。
