## 1. 分类判定规则（一眼三问）

一份文档在写/读时，依次回答三个问题，命中即归类：

| 序 | 判定问题 | 实录类（RECORD） | 意图类（INTENT） |
|----|----------|------------------|------------------|
| a | 时间轴：讲的是过去还是未来？ | 过去已发生 | 未来要做 |
| b | 动词：用了哪个词？ | 已 / 完成 / 部署 / 上线 | 将 / 计划 / 拟 / 待 |
| c | 可验证性：能否绑定 commit hash + 验证命令？ | 能 | 不能 |

**判定顺序**：先看 a 时间轴；含糊时看 b 动词；仍含糊时看 c 可验证性。
**硬规则**：一份文档只要含「声称已发生」的陈述，就必须归实录类并绑定验证锚点；不得以意图类身份写"已完成/已上线"。

## 3. 文件头模板

### 3.1 实录类（RECORD）

```markdown
> 文档类别：实录（RECORD）
> 最后核对时间：YYYY-MM-DD HH:MM CST
> 验证命令：<引用 Confirmation 注册表条目，如 `bash verify.sh grv_keys`>
> 真源锚点：commit <hash> / 容器内实测 <对象=值>
```

### 3.2 意图类（INTENT）

```markdown
> 文档类别：意图（INTENT）
> 状态：未实施 | 进行中 | 已实施
> 状态时间：YYYY-MM-DD
> （若「已实施」必须填）实施实录：<CHANGELOG 或 operations 路径> @ commit <hash>
```

## 4. 单向状态机

```
意图（未实施）→ 实施（进行中）→ 完成（已实施，链回实录条目）
                                        ↓
                              实录类文档（验证通过才合入）
```

**禁止路径**：
- 意图类直接写「已完成/已上线」而不链回实录条目 = 预告片当实况（案例 7：CHANGELOG 声称 rsync --delete 已移除、代码未改；案例 3：开阳 D3 迁移文档超前于 commit）
- 实录类写「计划/将」类陈述 = 类别污染，应拆回意图类

## 5. 注意事项

1. **存量改造用归档保留，不物理删除**：重分类时 mv 到 docs/archive/ 或加类别标记；*.bak-20260806 先例可复用。理由：历史上下文是排障资产，物理删除不可逆。
2. **AI 记忆接入**：AI 生成文档按本规范文件头模板走；读取时以实录类 + 验证结果为准，意图类不得作为状态断言引用。
3. **与方向 A/C 对齐**：本规范的「验证命令」一律引用方向 C 的 Confirmation 注册表；「真源锚点」以方向 A 仲裁表为准。规范本身是规则，落地校验靠 C 的命令巡检。
