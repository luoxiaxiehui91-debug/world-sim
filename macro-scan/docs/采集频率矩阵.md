# 天枢采集频率矩阵（macro-scan）

> 最后更新：2026-08-14 14:05 GMT+8（7 源批量提频：OpenSky I30 / 地震 I5 / 灾害 I15 / 加密 I10 / 加密冗余 I5 / 防务 RSS I60 / 能源 I60——50% 水位×源更新速度双约束）
> 目的：把"天枢贴近信息源限制频率采集"**落地为逐源可执行的频率决策**，避免盲目高频触发限流/封号（用户核心担忧）。
> 数据来源：**代码实况核对**（各 `fetch_*.py` 头部注释 + `scheduler.py` JOBS + `fetcher_base.py` 节流机制），不依赖 07-29 信息源手册（S: 盘按铁律不可信）。

---

## 一、边界规则（用户 2026-07-31 拍板）

1. **安全水位 ≤ 50%**：稳定态采集量 ≤ 各源 rate-limit 的 50%，留余量给重试/回填/突发。rate-limit 是**天花板/红线，不是目标**——贴限额打=封号路径。
2. **代理集中（先试试看）**：加密等高频源走共享 NAS 代理 `192.168.31.108:7890`。**限速主体是代理 IP**——多个源共享同一出口 IP，单源"安全水位"不能各算各的，必须按"该代理 IP 对各目标服务的请求量"分别核算（不同目标服务各自限流，互不挤占；同一目标服务多源同打才冲突）。
3. **事件源提频**：地震/火点等实时事件源进**事件档**（≤15min / 事件驱动），逻辑正确。
4. **逐源核实**：每个源都核对**上游实际更新频率** + **限流**，二者取窄；"跟着信息源的更新频率走"= 不慢于源更新、也不无意义地快于需求。

---

## 二、档位定义（tier）

| 档位 | 间隔 | 适用 |
|---|---|---|
| **事件档** | ≤15min 或事件驱动 / webhook | 实时 feed（地震、火点）、可更高频的加密 |
| **小时档** | 30–60min | 部分新闻流、部分 FX |
| **日档** | 1/日 | FRED 日序列、ECB/Frankfurter、能源、商品、News 聚合、GPR、制裁 bulk、HDX、OpenSky、BDI |
| **周档** | 1/周 | GDELT 聚合、NFCI（本身周频） |
| **月档** | 每月1日（dom=1） | AkShare 中观、FAO、ONI（NOAA 上游仅月更）、气候、慢变量 |
| **年档** | 年度 | GISS 温度异常（NOAA 上游仅年更）、SIPRI 年鉴（手工维护） |

> **核心原则：慢状态 vs 快事件显式拆分**——慢状态（ONI 月、GISS 年、FRED 日序列、FAO 月）提频无意义；快事件（地震、火点、极端天气）进事件档。气候模块混三档，lumping 会同时漏判（已核实）。

## 三、全局节流机制现状

- `fetcher_base.py`：每个 fetcher 有 `rate_interval`（请求间固定 sleep，秒）；`429/5xx` 指数退避重试（`base_backoff=2s`，`wait = 2^n`）；`4xx` 不重试直接降级。**已有 429 保护**，但"50% 安全水位"是**规划规则，代码未强制**——靠 scheduler 调度间隔执行。
- **代理共享 IP 风险**：绝大多数源走 `192.168.31.108:7890`，限速主体是代理 IP。建议后续加一个"代理 IP 对各目标服务日请求量"监控（非本矩阵范围）。

## 五、关键风险源详述

### ⚠ A. CoinGecko（#6）—— 月限额是硬约束
- Demo 档 **100 RPM / ~1万请求/月**（免 key）。宏观用途日频足够，但若要"crucix 级信息流丰富度"提到 15min：96/日 ≈ 2880/月，**仍 < 50%×1万=5000，安全**。
- **红线**：任何 ≥5min（288/日 ≈ 8640/月）即超 50% → **加密最高 15min，绝不可到分钟级**（分钟级 43,200/月 直接爆月限额）。
- 代理：走 `192.168.31.108:7890`，限速主体是代理 IP，但 CoinGecko 按 IP 限流——加密源独享该目标，不与其他源冲突。

### ⚠ B. OpenSky（#17）—— 匿名限额最严，绝不提频
- 匿名档官方限额严格（约 400 请求/日量级，且频控随匿名态收紧）。当前日频（1/日）合理；**提频（事件档）将迅速触顶封禁**。
- 如需更高频，必须申请 OpenSky 账号 key 提高限额——否则维持日档。

### ⚠ C. News（#12）—— 双源并行 30min 提频（08-14，用户要求 50% 水位保实时）
- **GDELT DOC 2.0**（主源，免费无 key）：每 5 秒 1 请求硬限速 + ~5000/天配额；I30 后 48 请求/日 ≈ 0.96% ≪ 50%。**GDELT 配额大，50% 用不完，实际受自身 5s 限速约束（即使用 5min 档 288/日=5.8% 也安全）**。
- **MarketAux**（增强，apiKey 免费档 ~100/天）：**I30 = 48 请求/日 ≈ 48%，正好贴 50% 上限（用户拍板的实时性上限）**；**再提 15min = 96/日 = 96% 破红线，禁止**。
- ~~Currents~~（2026-08 注册入口消失）/ ~~Sugra~~（api.sugra.ai 域名不存在）——已废弃摘除。

### ⚠ D. USGS 地震 / 灾害（#9 #11）—— 提频安全，推荐事件档
- USGS `2.5_day.geojson` 是**实时 feed**（过去 24h M≥2.5），慷慨无硬限。当前 4×/日（6h 间隔）对实时事件偏稀。
- **建议提到事件档 15–30min**（48/日 ≪ 限额），与"事件源提频"决策一致。灾害信号（含 seismic）一并提到事件档。

### ✅ E. FIRMS 火点（#24）—— 2026-07-31 已完成独立（守 AGPL 边界）
- 已新建 `fetch_firms.py` **纯重写直连 NASA FIRMS API**（VIIRS_SNPP_NRT+NOAA20_NRT，DAY_COUNT=2 贴近 Crucix 24-48h 窗口），落盘 `firms_fire.json`，日档 0908 调度（先于 climate 0910）。零借鉴 Crucix 代码，守 AGPL-3.0。
- `fetch_climate_signals` 改为**优先读直连文件、Crucix 兜底**（过渡期）。⚠ 顺带修复 Crucix 路径长期 bug：Crucix 返回 `det/night/hc` 无 `hotspots`，原读取逻辑致 `total_hotspots` 恒为 0——直连产出真实值。
- Crucix 退场后火点零断链（直连已就绪）。

### ✅ F. World Bank / SotW 代理（#4）—— 2026-07-31 实测已解决
- 既有经验（用户记忆）：**"World Bank/SotW 必须直连，走代理 SSLEOFError"**。
- 但 `fetch_world_macro.py` 代码**显式设 `PROXY_URL=192.168.31.108:7890` 并传给 self.request**——与记忆相反。
- **实测（2026-07-31）**：容器内经代理请求 WB 与 SotW 均返回 **HTTP 200**（WB len=2511、SotW len=144188）。**旧记忆 stale，代码正确，无需改。**
- 这是连续性协议抓到的典型"记忆 stale vs 代码"——已澄清，断上下文后不再复活。
